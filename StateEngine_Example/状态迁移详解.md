# 用数据库选择理解分层状态迁移

例程对应的场景是：从首页进入数据库选择页之前，先检查是否有数据库，并初始化选择页；而在选择页按上、下键时，只改变选中项并刷新页面，不应再次执行整页初始化。删除流程则先进入工作画面，再检查删除后的数据。

## 1. 对应的状态和结构体

| 状态对象 | `autoFlg` | 入口回调 | 作用 |
|---|---:|---|---|
| `StateHome` | `NO` | `DisplayScreen` | 等待用户进入选择页 |
| `StateDatabaseEntry` | `YES` | `CheckDatabaseSelect` | 进入选择页前检查是否有数据 |
| `StateDatabaseSelect` | `NO` | `DisplayScreen` | 等待页面内按键 |
| `StateDatabaseEmpty` | `NO` | `DisplayScreen` | 显示没有数据的结果 |
| `StateDeleteConfirm` | `NO` | `DisplayScreen` | 等待确认或取消 |
| `StateDeleteWorking` | `NO` | `DisplayScreen` | 先显示工作画面，等待外部执行事件 |
| `StateDeleteCheck` | `YES` | `CheckAfterDelete` | 删除后自动检查剩余数据 |

`DatabaseContext` 汇总模拟数据库、当前选择和调试计数。每个 `StateType_t` 状态对象仍指向自己的 `StateTable_t` 规则数组；本例没有改变引擎结构。

## 2. 为什么入口检查要设为 `YES`

初始有 3 条数据，从首页按确认：

```text
StateHome
   -- KEY_ENTER / DummyFunc --> StateDatabaseEntry
   -- 进入回调 CheckDatabaseSelect 返回 EVENT_DB_OK -->
   -- 自动匹配入口规则 / InitDatabaseSelect --> StateDatabaseSelect
   -- 进入回调 DisplayScreen --> 返回主循环
```

`StateDatabaseEntry.autoFlg = YES` 的意义是：执行 `CheckDatabaseSelect` 后，引擎把其返回值作为下一轮触发值，**在同一次 `StateEngine(KEY_ENTER)` 调用内**继续查 `DatabaseEntryRules`。有数据时，该规则先调用 `InitDatabaseSelect`，再进入选择页面；无数据时直接进入 `StateDatabaseEmpty`。

如果入口状态改为 `NO`，检查回调虽会执行，但引擎马上返回，不会在这次调用中查入口规则。初始化和页面跳转因此不会自动发生，主循环下一次传入的外部事件还会覆盖原触发值。

## 3. 页面内部为什么不执行重初始化

`StateDatabaseSelect.autoFlg = NO`，上、下键规则的目标仍是 `&StateDatabaseSelect`：

```text
KEY_DOWN → MoveDatabaseNext → StateDatabaseSelect → DisplayScreen → 返回
```

回到同一状态时仍会执行该状态的入口回调 `DisplayScreen`，但不会经过 `StateDatabaseEntry`，也不会调用 `InitDatabaseSelect`。终端中 `INIT` 不变、`DISPLAY` 增加，可直接观察这种区别。这里的“重/轻”是逻辑职责划分；示例的初始化仅重置选择项并计数，没有声称测量实际性能。

## 4. 两个回调与指针切换的顺序

以首页按确认、有数据为例：

| 步骤 | 左侧：当前结构体与指针 | 右侧：执行动作 |
|---|---|---|
| 1 | `stateInfo.state → StateHome`，`atTable → HomeRules` | 按 `KEY_ENTER` 查表 |
| 2 | `TblPtr → HomeRules[1]`；当前状态仍为 `StateHome` | 执行命中规则的后处理 `DummyFunc` |
| 3 | 规则的 `nextState → StateDatabaseEntry` | `stateInfo.state = GetNextState(&TblPtr)`；**此时**切换当前状态 |
| 4 | 当前状态为 `StateDatabaseEntry`，`autoFlg = YES` | 跳过历史保存，执行其入口 `CheckDatabaseSelect`，返回 `EVENT_DB_OK` |
| 5 | `stateInfo.trigger = EVENT_DB_OK`，`atTable → DatabaseEntryRules` | 继续查表，`TblPtr → DatabaseEntryRules[1]` |
| 6 | 当前状态仍为 `StateDatabaseEntry` | 先调用该规则的后处理 `InitDatabaseSelect` |
| 7 | 规则目标为 `StateDatabaseSelect` | 切换当前状态、记录历史、调用目标入口 `DisplayScreen` |
| 8 | 当前状态的 `autoFlg = NO` | 返回主循环，渲染页面并等待输入 |

`StateFindTable()` 改变的是规则指针 `TblPtr`，不是 `stateInfo.state`；每条规则的 `nextState` 是静态配置，不因匹配而被改写。`afFuncPtr` 是当前规则的后处理，`bfFuncPtr` 是目标状态的进入前处理；规则回调返回值传给目标入口，只有目标状态自动迁移时，其入口返回值才用于下一轮查表。

## 5. 删除工作状态为什么是 `NO`

确认删除后，`StateDeleteWorking` 是 `NO`，引擎执行 `DisplayScreen` 后返回。主循环调用 `ScreenRenderCurrent` 打印工作画面，然后在下一轮模拟发出 `EVENT_DELETE_EXECUTE`；工作状态匹配此事件，先调用 `DeleteDatabaseContent`，再进入 `StateDeleteCheck`。

`StateDeleteCheck` 是 `YES`：其入口根据剩余数量返回 `EVENT_DB_OK` 或 `EVENT_DB_EMPTY`，同一次调用内自动匹配对应规则。前者先重新初始化再进入选择页，后者进入空数据页。此演示的执行事件由主循环立即模拟，不代表真实数据库操作已异步完成；真实工程需由调度器或设备事件驱动。

## 6. 历史及调试

初始化不保存首页，所以 `main.c` 在初始化后发送一次 `EVENT_HOME_READY`，使首页自迁移并入栈。进入选择页后历史为 `[Home, DatabaseSelect]`，从选择页使用 `PreviousState` 可回到首页；自动入口状态不入栈。取消删除时直接指定选择页，引擎会截断历史中选择页之后的记录。删除全部数据后，空页显式返回首页，避免把删除工作状态当作返回目标。

建议在 `StateFindTable`、`stateInfo.state = GetNextState(&TblPtr)`、`CheckDatabaseSelect`、`InitDatabaseSelect`、`DisplayScreen`、`DeleteDatabaseContent` 和 `CheckAfterDelete` 设置断点；观察 `stateInfo`、`TblPtr`、`g_database`、`stateStack.stackTop`。注意 `g_database` 是文件私有变量，调试器需在其作用域中查看。

自动状态不会保存历史；未匹配规则时引擎直接返回，且自动循环缺少次数限制。历史栈容量为 25、未做越界检查；空历史回退可能产生空指针。完整操作和运行说明见本目录 README。
