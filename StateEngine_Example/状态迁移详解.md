# 用数据库选择理解分层状态迁移

例程采用统一的画面分层：每次切换画面，先进入 `autoFlg = YES` 的中间过渡状态表，由它检查、初始化或解析历史，再自动进入 `autoFlg = NO` 的目标画面状态表。同一画面内的移动和输入直接自迁移，不经过跨画面初始化。这个结构同样适用于返回、错误提示、空数据提示和删除工作画面。

## 1. 状态表与迁移表的关系

| 状态表（`StateType_t`） | `autoFlg` | 前处理函数 | 作用 |
|---|---:|---|---|
| `StateHomeEntry` | `YES` | `DummyFunc` | 启动准备或提示页返回时，自动进入首页 |
| `StateHome` | `NO` | `DummyFunc` | 等待用户进入选择页 |
| `StateDatabaseEntry` | `YES` | `CheckDatabaseSelect` | 进入选择页前检查是否有数据 |
| `StateDatabaseSelect` | `NO` | `DummyFunc` | 等待页面内按键 |
| `StateContentEntry` | `YES` | `CheckDatabaseItem` | 检查数据库，正常分支初始化内容页光标 |
| `StateDatabaseContent` | `NO` | `DummyFunc` | 查看选中的模拟数据库内容 |
| `StateEditEntry` | `YES` | `CheckCell` | 检查数据库和单元格，正常分支备份原值 |
| `StateDatabaseEdit` | `NO` | `DummyFunc` | 按范围条件编辑模拟内容 |
| `StateDatabaseEmpty` | `NO` | `DummyFunc` | 显示没有数据的结果 |
| `StateDatabaseError` | `NO` | `DummyFunc` | 显示模拟故障或无效选择等入口检查错误 |
| `StateConfirmEntry` | `YES` | `CheckDatabaseItem` | 检查待删除条目，再进入确认画面 |
| `StateDeleteConfirm` | `NO` | `DummyFunc` | 等待确认或取消 |
| `StateWorkingEntry` | `YES` | `CheckDatabaseItem` | 再次检查删除目标，再进入工作画面 |
| `StateDeleteWorking` | `NO` | `DummyFunc` | 先显示工作画面，等待外部执行事件 |
| `StateDeleteCheck` | `YES` | `CheckAfterDelete` | 删除后自动检查剩余数据 |
| `StateDeleteResume` | `YES` | `DummyFunc` | 通过 `STATE_ANY` 无条件进入选择页 |
| `StateBackEntry` | `YES` | `DummyFunc` | 自动通过 `PreviousState` 逐级回退，不重复初始化 |
| `StateHomeBackEntry` | `YES` | `DummyFunc` | 后处理定位历史首页，再通过 `FormEntryState` 自动回到首页 |

`StateType_t` 定义状态表，`StateTable_t` 定义迁移表。状态表通过 `transTbl` 指向迁移表数组，通过 `transNum` 记录条目数。数组中的每个迁移表项包含 `trigger` 迁移条件、`onExit` 后处理函数和 `nextState` 目标状态表指针；状态表保存 `onEnter` 前处理函数、`autoFlg` 自动迁移标志和画面 ID。

例如，`StateDatabaseSelect.transTbl` 指向 `DatabaseSelectRules`，其中 `KEY_DOWN` 表项的 `nextState` 又指向 `StateDatabaseSelect`，表示页内自迁移。`DatabaseContext` 汇总模拟数据库、当前选择和模拟故障标志；普通状态表无需额外前处理时使用 `DummyFunc`，画面由主循环渲染。

## 2. 为什么每次画面切换都先经过 `YES`

初始有 3 条数据，从首页按确认：

```text
StateHome
   -- KEY_ENTER / DummyFunc --> StateDatabaseEntry
   -- 前处理 CheckDatabaseSelect 返回 EVENT_DB_OK -->
   -- 自动匹配入口迁移表项 / InitDatabaseSelect --> StateDatabaseSelect
   -- 前处理 DummyFunc --> 返回主循环
```

`StateDatabaseEntry.autoFlg = YES` 的意义是：执行入口状态表的前处理 `CheckDatabaseSelect` 后，引擎把返回值作为下一轮触发值，**在同一次 `StateEngine(KEY_ENTER)` 调用内**继续查询 `DatabaseEntryRules` 迁移表。有数据时，命中的迁移表项先调用后处理 `InitDatabaseSelect`，再切换到选择页状态表；无数据时切换到 `StateDatabaseEmpty`。

首页按 `E` 开启入口模拟故障后，`CheckDatabaseSelect` 返回 `EVENT_DB_ERROR`；自动查询迁移表，命中错误条件的表项，执行 `DummyFunc` 后切换到 `StateDatabaseError`。按 `C` 返回首页，再按 `E` 关闭故障。正常、空数据和错误均由迁移表项明确配置，并非靠引擎自动推断。错误标志仅影响入口检查，不影响删除后的检查。

如果入口状态表的 `autoFlg` 改为 `NO`，检查前处理虽会执行，但引擎马上返回，不会在这次调用中查询入口迁移表。初始化和页面跳转因此不会自动发生，主循环下一次传入的外部事件还会覆盖原触发值。

其他跨画面路径采用同样结构：

```text
StateDatabaseSelect (NO) → StateContentEntry (YES) → StateDatabaseContent (NO)
StateDatabaseContent (NO) → StateEditEntry (YES) → StateDatabaseEdit (NO)
StateDatabaseSelect (NO) → StateConfirmEntry (YES) → StateDeleteConfirm (NO)
StateDeleteConfirm (NO) → StateWorkingEntry (YES) → StateDeleteWorking (NO)
```

内容、编辑、确认和工作入口的迁移表均包含 `EVENT_DB_ERROR`、`EVENT_DB_EMPTY`、`EVENT_DB_OK` 分支。入口前处理只返回检查结果，正常分支的后处理按需执行 `OpenDatabase` 或 `BeginEdit`，错误和无数据分支自动进入提示画面。无需条件判断的首页入口和回退入口使用 `STATE_ANY` 无条件匹配。所有过渡状态表都使用 `SCREEN_ID_NONE`，不显示，也不入历史栈。

## 3. 页面内部为什么不执行重初始化

`StateDatabaseSelect.autoFlg = NO`，上、下键对应迁移表项的 `nextState` 仍指向 `&StateDatabaseSelect`：

```text
KEY_DOWN → MoveDatabaseNext → StateDatabaseSelect → DummyFunc → 返回
```

回到同一状态表时仍会执行其前处理函数 `DummyFunc`，但不会经过入口状态表 `StateDatabaseEntry`，也不会调用 `InitDatabaseSelect`。可在 `CheckDatabaseSelect`、`InitDatabaseSelect` 和 `MoveDatabaseNext` 设置断点，对比跨页面进入与页内操作。这里的“重/轻”是逻辑职责划分；示例的初始化仅重置选择项，没有测量实际性能。

内容页的方向键同样直接回到 `StateDatabaseContent`，不会经过 `StateContentEntry` 或重置光标。编辑页每次输入直接回到 `StateDatabaseEdit`，不会重新执行 `BeginEdit`，因此取消时仍能恢复进入编辑前的原值。

## 4. 后处理、前处理与指针切换的顺序

以首页按确认、有数据为例：

| 步骤 | 左侧：当前结构体与指针 | 右侧：执行动作 |
|---|---|---|
| 1 | `stateInfo.state → StateHome`，`StateHome.transTbl → HomeRules` | 按 `KEY_ENTER` 查询迁移表 |
| 2 | `TblPtr → HomeRules[1]`；当前状态表指针仍指向 `StateHome` | 执行命中迁移表项的后处理 `DummyFunc` |
| 3 | 迁移表项的 `nextState → StateDatabaseEntry` | `stateInfo.state = GetNextState(&TblPtr)`；**此时**切换当前状态表指针 |
| 4 | 当前状态表为 `StateDatabaseEntry`，`autoFlg = YES` | 不将其指针入栈，执行前处理 `CheckDatabaseSelect`，返回 `EVENT_DB_OK` |
| 5 | `stateInfo.trigger = EVENT_DB_OK`，`StateDatabaseEntry.transTbl → DatabaseEntryRules` | 继续查询迁移表，`TblPtr → DatabaseEntryRules[2]` |
| 6 | 当前状态表指针仍指向 `StateDatabaseEntry` | 先调用命中迁移表项的后处理 `InitDatabaseSelect` |
| 7 | 迁移表项的目标为 `StateDatabaseSelect` | 切换状态表指针、记录历史、调用目标状态表前处理 `DummyFunc` |
| 8 | 当前状态表的 `autoFlg = NO` | 返回主循环，渲染页面并等待输入 |

`StateFindTable()` 改变的是迁移表项指针 `TblPtr`，不是当前状态表指针 `stateInfo.state`；每个迁移表项的 `nextState` 是静态配置，不因匹配而被改写。`onExit` 属于命中的迁移表项，`onEnter` 属于目标状态表；后处理返回值传给目标前处理，只有目标状态表启用自动迁移时，其前处理返回值才用于下一轮迁移表查询。

## 5. 删除工作状态为什么是 `NO`

确认删除后，先经过 `StateWorkingEntry`（`YES`）检查目标，再自动切换到 `StateDeleteWorking`（`NO`）。引擎执行画面状态表的前处理 `DummyFunc` 后返回，主循环调用 `ScreenRenderCurrent` 打印工作画面，然后在下一轮模拟发出 `EVENT_DELETE_EXECUTE`；引擎在工作状态表的迁移表中匹配此事件，先调用表项后处理 `DeleteDatabaseContent`，再切换到 `StateDeleteCheck`（`YES`）。入口过渡和可显示的工作状态是两个层次；将工作状态本身设成自动迁移，会在主循环显示它之前离开该状态。

`StateDeleteCheck` 状态表的 `autoFlg` 为 `YES`：其前处理根据剩余数量返回 `EVENT_DB_OK` 或 `EVENT_DB_EMPTY`，同一次调用内自动命中对应迁移表项。前者切换到自动迁移状态表 `StateDeleteResume`，再由其迁移表的 `STATE_ANY` 条件无条件匹配并初始化选择页；后者进入空数据页。`STATE_ANY` 按迁移表数组顺序生效，兜底表项应放在末尾。此演示的执行事件由主循环立即模拟，不代表真实数据库操作已异步完成；真实工程需由调度器或设备事件驱动。

内容页通过方向键或 `W/A/S/D` 选择两列表格中的单元格，按 `Enter` 先进入 `StateEditEntry` 检查并备份原值，再自动切换到编辑状态表：数字、大写和小写字母，以及分段配置的 ASCII 符号区间分别由迁移表中的范围条件匹配，命中后执行后处理，在当前单元格末尾追加字符。保存保留修改；取消先在编辑页的后处理中恢复原值；两者都再经 `StateBackEntry` 自动回到内容页。编辑按键与普通页面的快捷键分开处理，内容仅在本次运行的内存中保存。

## 6. 历史及调试

历史栈保存画面状态表指针。初始化不保存首页状态表，所以 `main.c` 在初始化后发送一次 `EVENT_HOME_READY`，先进入 `StateHomeEntry`（`YES`），再自动进入 `StateHome`（`NO`）并保存其指针。进入选择页后历史为 `[Home, DatabaseSelect]`，过渡状态表不入栈。选择页返回和取消删除都先进入 `StateBackEntry`，其唯一迁移表项指向 `PreviousState`，引擎据此回退到上一画面。空数据页和错误页返回时经过 `StateHomeEntry` 再进入首页，历史截断至首页，不返回删除工作画面。

在选择页经 `StateContentEntry` 进入内容页后，历史仍为 `[Home, DatabaseSelect, DatabaseContent]`。按 `C` 时先进入 `StateBackEntry`，再通过 `PreviousState` 弹出内容页指针、取得选择页指针，保留当前选择。编辑页保存或取消也通过同一回退过渡表返回内容页，不重新经过 `StateContentEntry`，所以光标不会重置。

内容页按 `H` 时先进入 `StateHomeBackEntry`（`YES`）。它的迁移表项后处理 `SelectHomeFromHistory` 从栈顶向前定位首页，把有效栈顶截断至首页；随后引擎将特殊状态表占位 `FormEntryState` 解析为新的栈顶状态表指针，不再弹栈，自动进入首页，历史变为 `[Home]`。指定目标的定位由回退过渡态的后处理完成；如果历史中没有首页，原栈保持不变，最终重新进入原栈顶指向的状态。例程启动准备时会通过 `StateHomeEntry` 保存首页，保证正常操作能找到首页。

建议在 `StateFindTable`、`stateInfo.state = GetNextState(&TblPtr)`、`CheckDatabaseSelect`、`CheckDatabaseItem`、`CheckCell`、`OpenDatabase`、`BeginEdit`、`DeleteDatabaseContent` 和 `SelectHomeFromHistory` 设置断点；观察 `stateInfo.state` 先指向自动过渡状态表，再指向画面状态表，以及 `stateHistory.top` 只记录画面状态表。也可观察 `TblPtr`、`g_database`；后者是文件私有变量，调试器需在其作用域中查看。

自动迁移状态表不会保存到历史栈；未命中迁移表项时引擎直接返回，且自动循环缺少次数限制。历史栈容量为 25、未做越界检查；空历史回退可能产生空指针。完整操作和运行说明见本目录 README。
